# Task 002: Layer 2 -- extend the port derivation to the full set (210 faces)

## Objective

Card 001 built the derivation and proved it on 11 pilot + 3 holdout faces.
Card 002 extends it -- **without adding per-card branches** -- to run
cleanly on every face in `data/normalized/faces.jsonl` and produce a
`data/graph_global/card_ports.jsonl` with:

  - 210 port records (one per face)
  - **0 unresolved abilities**
  - **0 undeclared concepts**
  - **0 selector-in-name anti-pattern hits**
  - **2135 typed edges** across properties / installs / consumes / produces / costs

The mechanism from Card 001 stays put. What changes is the *vocabulary* and the
*trigger table*: whatever the reviewed extraction says across the whole set
must land in the port as a typed edge, not in `unresolved`.

## What Card 002 changed

### Vocabulary

  - `data/vocabulary/op_map.jsonl`: **33 -> 185 rows (+152)**. New rows in five buckets:
      1. Aliases for verbs that entered as `effect:` / `action:` / `type:`
         rather than `op:` (same predicate, extra source_key row).
      2. New predicates for common Magic actions the pilot never exercised:
         `PRODUCES_MANA`, `TUTORS`, `GAINS_LIFE`, `UNTAPS`, `SCRIES`, `MILLS`,
         `COUNTERS_SPELL`, `FIGHTS`, etc.
      3. Novel mechanics from HOB: `RECRUIT`, `ADVENTURE`, `TYPECYCLING`,
         `KICKER`, `FLASHBACK`, `BEHOLDS`, `AMASSES`, and one keyword-key
         verb (see KEYWORD_VERB_KEYS below).
      4. Conditional modifiers: `MODIFIES_COST`.
      5. Structural markers: `MODAL_MARKER`, `RESTRICTION`.

  - `data/vocabulary/concepts.jsonl`: **32 -> 135 rows (+103)**. New rows are:
      - **37 Event concepts (29 in the initial batch + 8 more added when we found the specific-selector event names had to be declared)** for the 89 distinct trigger phrases now handled
        by `map_trigger_to_event()` (phase-step, sacrifice, draw, damage,
        exile-replacement, saga-chapter, dwarf/equipment enters, land enters,
        artifact enters, this-permanent enters, and specific triggers like
        `event:total-attack-power-12-or-greater`).
      - **66 ObjectClass / Keyword concepts (48 supertype/subtype from the normalized face type_lines + 18 ability-keyword concepts from the extraction)** for every supertype (basic,
        legendary), subtype (dwarf, hobbit, wizard, mountain, forest, ...),
        and keyword ability (deathtouch, flashback, first strike, ...)
        harvested from the normalized faces and the extraction. This closes
        the last undeclared-concept gap so validation reports zero.

### Derivation

  - `src/hobkg/ports.py::map_trigger_to_event()` grew from a **6-branch pilot
    map** to a **structured, ordered matcher** covering all 89 trigger phrases
    observed across 210 faces. Ordering matters (saga-chapter before generic
    counter; enter-selectors before bare `_enters`). Bare forms (`dies`,
    `attacks`, `_enters`) and subject-name self-references (`smaug_attacks`,
    `The Master of Lake-town dies`, `Dain enters the battlefield`) all fold
    to the correct `event:this-creature-*`.

  - `KEYWORD_VERB_KEYS = ("amass",)` -- some Magic keyword-actions arrive as
    a top-level *key* in the effect dict (`{"amass": {...}}`) rather than a
    *value* on `op` / `effect` / `action` / `type`. When the standard keys
    are absent, the effect loop tries these fallback keys with
    `source_key == verb`. `op_map.jsonl` declares them the same way.

  - `derive_all(..., all_faces=True)` -- new mode that runs the derivation
    on every face in `data/normalized/faces.jsonl` using the full Phase-3
    extraction. `--all` CLI flag exposes it. `--all` and `--face` are
    mutually exclusive.

  - Ability-level cost lifting expanded from **mana-only** to **eight cost
    families**: mana, sacrifice, tap, life, discard, crew, restriction, and
    additional_cost (Stir Up Trouble). The pilot silently dropped every
    non-mana ability-level cost -- Allure of Power's "sacrifice a creature",
    Lonely Mountain's `{T}`, My Precious's "pay 2 life", the discard costs
    on cycling, etc. -- because the effect processor only saw them when an
    accompanying effect referenced them. The cost loop now emits typed
    edges (SACRIFICES / TAPS / PAYS_LIFE / DISCARDS / CREW / RESTRICTION)
    with `purpose="cast"` for spell_effect abilities and
    `purpose="activation"` for activated abilities.

  - Descriptor sweep, pass 2:
      * `PRODUCES_MANA` lifts `mana` / `color` / `colors` / `options`
        (Forest gets `mana:"{G}"`, Elvenking's Halls gets
        `options:["G","U"]`).
      * Damage effects lift `amount` / `target_text` / `distribution`.
      * Cost detection accepts `{"cost": "mana", "value": "..."}`
        alongside the existing op/type shapes.
      * Every edge with a natural-language target now carries
        `target_text` (Gone Fishing, Gandalf, Elvenking's Harper).
      * Trigger `condition` / `filter` / `subject` / `timing` /
        `frequency` / `note` lifted onto the `TRIGGERS_ON` edge.
      * Effect descriptor lift extended with `ability_text`, `mana`,
        `options`, `distribution`, `unless`, `references_rule`,
        `to_zone` / `from_zone` / `under_control` / `enters_tapped` /
        `searched_type`, `modification`, `power_delta` /
        `toughness_delta` / `delta`.

  - Manual-review sweep (buckets 1-4):
      * Bucket 1: token spec lift. `CREATES_TOKEN` / `GIFTS` /
        `CREATES_OBJECT` edges resolve the reference against Scryfall's
        token index and attach a full `token` block (name / type_line /
        subtypes / power / toughness / colors / oracle_text).
        Recognises reference fields `token`, `token_ref`, `gift_object`,
        `token_type`, `creates`, `spawn`. Modal effects (`{op: modal,
        options: [...]}`) also unpack their `options` into a `branches`
        list on the entry, each branch a typed sub-edge with its own
        predicate and (if a token-creator) resolved token spec.
      * Bucket 2: blank-endpoint fill. The entry builder lifts every
        descriptor field the extraction carries (`subject`, `adds_type`,
        `note`, `detail`, `text`, `keyword_ability`, `granted_text`,
        `permission`, `restriction`, `scales_with`, `scope`, `mode`, ...)
        so edges that used to render as bare `GRANTS_PERMISSION` or
        `REPLACES` carry the extraction's own descriptor as endpoint.
      * Bucket 3: effect-level `condition` (singular) is now merged
        into the entry's `conditions` list, not just ab-level
        `ab.conditions`. Beorn the Fierce's conditional_draw is the
        pilot case.
      * Bucket 4: compound triggers split. "Enters or attacks" (Bifur,
        Dwalin, Bard's Company) emits both permanent-enters and
        creature-attacks; "Balin or another Dwarf enters" emits both
        permanent-enters and another-dwarf-or-equipment-enters.

  - Self-ETB triggers split by printed subject type. A trigger like
    "When this enchantment enters" fires ONLY when the card enters *as
    an enchantment* (CR 603.6a), so each printed subject type gets its
    own narrower event: `event:this-creature-enters`,
    `event:this-enchantment-enters`, `event:this-artifact-enters`,
    `event:this-aura-enters`, `event:this-equipment-enters`,
    `event:this-land-enters`. Card-name self-references and bare
    "enters" with no printed type word land on
    `event:this-permanent-enters`. Oracle wording is ground truth
    (`trigger.text` / `subject` / `note`), correcting the extractor's
    over-normalisation of "When Smaug enters" to the broad target.
    Consumers gate on "any creature ETB" by matching either
    `event:this-creature-enters` or (`event:this-permanent-enters` AND
    `IS_A obj:type:creature`).
  - "As this X enters" replacement effects (An Unexpected Party) route
    to `installs.REPLACES_ON` instead of `consumes.TRIGGERS_ON`. The
    signal is `ab.kind == "replacement"`. Same event vocabulary,
    different edge predicate: "reacts to the event" vs "changes what
    the event does".

  - Effect descriptor lift. The extraction carries fields the pilot
    dropped: `counter_type` (`"+1/+1"`, `"trample"`, `"lore"`, ...),
    `duration` (`"until end of turn"`), and `token` / `token_ref` /
    `token_type`. Every `ADDS_COUNTER` edge now names the counter, every
    duration-bounded grant records how long, and every token-creator
    names the token. Bifur, Melodic Rider's `ADDS_COUNTER` now reads
    `counter_type: "+1/+1"`; Beorn the Fierce reads
    `counter_type: "trample"` -- the graph can tell them apart.

  - Baseline power/toughness lifted into properties as `HAS_POWER` /
    `HAS_TOUGHNESS` edges (target `obj:power` / `obj:toughness`, numeric
    `amount` coerced from the string form; non-numeric values like `"*"`
    or `"1+*"` pass through verbatim). One edge each per creature or
    vehicle -- 226 new edges across 113 permanents. These are as
    intrinsic to a permanent's port as its type line.

  - Native-keyword detection extended past `ab.keyword`. The extraction
    schema-laxly encodes some native keywords inside an effect
    (`{"op":"keyword"}` or `{"op":"grant_keyword"}` on a static ability
    with no target/subject) rather than promoting them to `ab.keyword`.
    Dori's Trample, Smaug's Flying, Large Bear's reach/trample/haste all
    had this shape and were being wrongly emitted as `produces.GRANTS`.
    They now correctly land in `properties.HAS_KEYWORD`, and the ops are
    added to `consumed_verbs` so the effect loop does not re-emit them.
    Real grants (Bofur's Storied lifelink, "target creature gains X"
    spells) keep their GRANTS edge. Self-reference tokens count as
    no-target for the native branch: `this creature`, `this permanent`,
    `this card`, and the card's own name (Bejeweled Warg's Trample
    arrives with `target: "this creature"`; Ori's vigilance with
    `target: "Ori"`; Little Bear's flash with `subject: "this card"`).
    The branch also reads both `keyword` (singular) and `keywords`
    (plural) slots, and matches a wider set of extraction shapes:
    `op in {keyword, keyword_ability, grant_keyword}`, `effect in
    {grants_keyword, grant_keyword, keyword_ability, keyword}`,
    `type in {grant_keyword}`, plus any `op` starting with `grant_`
    that carries a keyword field.

  - Selector-in-name check now exempts `event:` targets. CR-defined trigger
    predicates legitimately embed a subject qualifier
    ("nontoken creature you control dies", "equipped creature deals combat
    damage") -- those are single, well-defined trigger patterns, not
    compound ObjectClass names. Non-event targets still fail the check.
