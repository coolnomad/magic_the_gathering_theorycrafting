# Task 016: T2, the bump against a cross-fitted learned baseline

## Objective

Fit the benchmark's third and last target formulation. T1 subtracted a **fixed**
historical proxy. T2 subtracts a **learned** one, and the learned baseline must
be cross-fitted so that no observation ever helps train the model that produces
its own baseline:

    m_hat_-i(S_i)                        the cross-fitted baseline, E[Y|S] out of fold
    B_i = Y_i - m_hat_-i(S_i)            the target actually fitted
    p_i = m_hat(S_i) + B_hat_i           the probability reconstructed from it

Same two representations as T0 and T1 -- **R0** skill only, **R1** skill plus
card identity -- through the same estimator, the same grid, the same frozen
folds, the same seed.

This is the third row H2 needs (section 14 predicts T2 > T1 > T0 in recovered
deck signal). It is a hypothesis, not an assumed result. This card produces the
row. It does not test the ordering and must not try.

No holdout is opened. No conclusion is drawn.

## Acceptance Criteria

- [ ] `T0_R0`'s run record is validated **before** its predictions are used: `target == "T0"`, `representation == "R0"`, `objective == binary`, `n_features == 1`, `seed` equal to the card's seed, and `split_sha256` matching `data/splits/split_manifest.json`. Any mismatch stops the run rather than silently residualizing against the wrong baseline
- [ ] The fitted target is `won - m_hat_-i(base_p)`, where the baseline vector is read from `T0_R0`'s **out-of-fold predictions**, joined on `obs_id`, failing if the join is not total
- [ ] **A test proves the baseline is out-of-fold and not the full-data refit.** It must assert both that the baseline vector equals `T0_R0`'s stored out-of-fold predictions *and* that those differ from the full-data booster's in-sample predictions on the same rows -- otherwise the assertion is satisfied by a model that leaked
- [ ] The estimator is called with the **regression** objective; `TARGET_OBJECTIVE[TARGET_T2]` records it
- [ ] `T2_R0` uses exactly one feature, `base_p`; `T2_R1` uses 194 -- identical assembly to cards 011 and 015, from the same frozen parquets, joined on `obs_id`
- [ ] **The development reconstruction uses the out-of-fold baseline**, `p_i = m_hat_-i(S_i) + B_hat_i`, not the full-data refit. Reconstructing development rows against a baseline fitted on those same rows would inject a leak that makes T2's development numbers incomparable with T0's and T1's. The report must state this, and state that card 017 uses the full-data `m_hat(S)` on holdout rows, where it is honest by construction
- [ ] The reconstruction is clipped into the unit interval using the panel's declared clip bound, and the number of rows clipped **at each end** is counted and reported
- [ ] The evaluation panel is applied **twice** per model: continuous on the bump, Bernoulli on the reconstructed probability against the raw `won` outcome
- [ ] The report states that only the **reconstructed-probability** metrics are comparable across T0, T1 and T2
- [ ] **`T2_R0` is reported as a cross-fitting diagnostic, not as a result.** `E[B|S] = E[Y|S] - m_hat(S)` is approximately zero by construction, so `T2_R0`'s predictions should sit near zero. The report must give their mean, standard deviation and range, and state plainly that a large systematic departure from zero indicates leakage or misfit in the baseline rather than recovered signal
- [ ] The report documents that **hyperparameter selection is not fold-honest**: the out-of-fold training is, but `chosen` was selected by cross-validation over all development folds, so fold k's baseline comes from a booster trained without fold k under hyperparameters informed by it. - [ ] A test asserts `--verify` fails when a T2 artifact is removed, so the check is demonstrably not vacuous
- [ ] `data/processed/MANIFEST.sha256` is unchanged by this card

- [ ] Re-fitting `T2_R0` with the same seed reproduces byte-identical predictions
- [ ] The report draws no comparison among T0, T1 and T2, and none between R0 and R1

## Notes

**The baseline already exists -- do not refit it.** `m(S) = E[Y|S]` fitted on
**R0** with the **binary** objective, predicted out of fold, is exactly what card
011 already produced as `T0_R0`. `data/runs/T0_R0_predictions.parquet` (a parquet, so deliberately **not** a
declared Input -- compact reads declared inputs as UTF-8 text and a binary file
crashes context assembly) is the out-of-fold `m_hat_-i(S_i)` -- 194,215 development rows, no NaN -- because
`estimator._out_of_fold_predictions` builds each fold's predictions from a
booster trained on the other folds, using the frozen folds and nothing else.
`data/runs/T0_R0.xgb` is the full-data refit `m_hat(S)`, for card 017. Reuse
both. Refitting an identical model would burn ~80s to produce the same numbers
and would let T2's baseline drift from the `T0_R0` that card 017 also scores,
which is the one thing that would make the T0/T2 contrast unreadable.

**Why a learned baseline at all.** T1 subtracts a proxy built by hand from a
historical win-rate bucket and a shrinkage rule. If that proxy is miscalibrated
-- and `T1_R0` measured that it is, slightly, with an out-of-fold r-squared of
0.0108 against its own residual -- then part of what T1's deck model recovers is
proxy error rather than deck quality. T2 replaces the hand-built baseline with
`E[Y|S]` estimated by the same learner, so the residual it hands the deck model
is what a good model of the skill representation could not already explain.
Whether that is a cleaner baseline is the question; section T2's purpose states
it as a question.

**Cross-fitting is the whole card.** A learned baseline is only a baseline if it
did not see the observation it is baselining. Fit `m` on everything, subtract,
and the residual is shrunk toward zero exactly where the baseline overfit, which
manufactures the appearance of a clean subtraction while destroying the signal
underneath. The frozen 5-fold split is what makes this checkable: each fold's
baseline comes from a booster trained on the other four, and card 009 already
implements it. The criterion demanding a test that the out-of-fold vector
*differs from* the in-sample one exists because an assertion that the baseline
"is the out-of-fold prediction" passes trivially if the two happen to be equal
-- and they would be equal if something had gone wrong.

**`T2_R0` is a control, not a model.** Under T2 the R0 features are the same `S`
the baseline was fitted on, so `E[B|S]` is approximately zero by construction
and `T2_R0` should predict close to nothing. That makes it the most informative
diagnostic in the card: if it finds substantial structure, the cross-fitting
leaked or the baseline underfit. Report its predictions' location and spread and
read them as a check on the machinery. Do not read a small non-zero value as
deck signal -- R0 contains no deck information at all.

**Two baselines, two places.** The out-of-fold `m_hat_-i` builds the training
residual *and* reconstructs development probabilities, so the development report
is honest about its own baseline. The full-data `m_hat` is for card 017, where
holdout rows never trained it and it is honest by construction. Using the
full-data model to reconstruct development rows would flatter T2 against T0 and
T1 for no reason other than leakage, and the two must not be swapped.

**What this card does not decide.** Card 017 opens the sealed holdout once and
scores every model through the same panel with the paired cluster bootstrap on
the differences. Until then T2 is one row of a table, recorded and
uninterpreted. Section 13 forbids reading a null incremental result as absence
of a deck effect.
