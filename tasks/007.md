# Task 007: Phase-1 audit report, and halt before model fitting

## Objective

Section 17 of the benchmark ends with two instructions: produce an audit report,
and stop for review before model fitting. This card is both.

It consolidates cards 003 through 006 into one document an operator can read end
to end and then decide whether the dataset is fit for the benchmark. It also
states, precisely, what Phase 2 is permitted to assume -- because the value of a
frozen dataset is that later cards inherit facts instead of re-deriving them,
and the facts have to be written down somewhere they cannot drift.

Nothing is fitted here. No holdout is opened. The deliverable is a report, a
reusable append-only checker, and a lab-notebook entry.

## Notes

**Why the append-only checker belongs here rather than in its own card.** This
repository has enforced append-only discipline on `LABNOTEBOOK.md` and
`CONVERSATION_LOG.md` since it began, and has never been able to check it. The
obvious check is wrong in a way that looks right: comparing
`git show HEAD:LABNOTEBOOK.md` against the working file reports a violation on
every append, because `* text=auto` stores LF in the blob while the working copy
is CRLF. Verified on 2026-09-07 -- the naive comparison failed on a change that
was in fact a clean 3712-byte append, and the same content compared at blob
level passed. `LABNOTEBOOK.md` also carries `-diff` in `.gitattributes`, so
there is no diff to eyeball as a fallback. A card that has to append to the
notebook is the natural place to build the check, and the tool then serves every
future card.

**Why this card halts rather than continues.** Section 16 orders the work: data
audit, then target benchmark, then representation benchmark, then causal
estimation. Section 17 says to stop for review before model fitting. The
substantive reason is that Phase 2's shape depends on what Phase 1 measured --
if within-draft deck changes are rare, game level and draft level nearly
coincide and the six Phase-2 fits are cheap; if they are common, the unit
matters and the cards look different. Writing Phase 2 before this report exists
would mean writing acceptance criteria against unmeasured facts, which is what
the quarantined pipeline did.

**What the "what Phase 2 may assume" section is for.** The failure this
repository has already suffered is two reports disagreeing about the same
comparison with nothing to adjudicate between them. Numbered claims pinned to
artifact hashes give the next phase something to verify against instead of a
recollection. If a Phase 2 card finds a hash mismatch, the dataset moved and the
comparison is void -- which is a much better outcome than discovering it in the
results.

**Uncertainty is a deliverable.** Section 13 of the benchmark forbids reading a
null incremental result as absence of a causal deck effect, and lists five
alternative explanations. The equivalent discipline at Phase 1 is to record what
could not be established. If card 003 found no historical skill buckets, or card
005 found bucket values outside the inherited `hist_w` map, those are findings
about the method that Phase 2 needs in front of it -- not gaps to paper over so
the report reads cleanly.
