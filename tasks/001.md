# Task 001: Layer 2 pilot -- the per-card port interface, ten faces

## Objective

Establish the **port record** -- what a card is, what it looks for, what it
offers -- as a first-class artifact, together with the **concept vocabulary**
and **selector grammar** it is written in. Prove all three on ten deliberately
awkward faces before committing to the remaining 183.

This is layer 2 of four:

    1  card text            data/normalized/faces.jsonl        COMPLETE (210 faces, 193 cards)
    2  per-card ports       card_ports.jsonl + vocabulary      THIS CARD (pilot: 10 faces)
    3  set-wide network     a VIEW over layer 2, never stored
    4  capacity projection  a sum over layer 2, ~200 dimensions

Layers 3 and 4 both read layer 2. Neither is a prerequisite for the other, and
neither may be built before layer 2 exists.

### The worked example

`Pinecone Strike` (`face:961e3023-...:0`), Instant {1}{R}:

    Choose one or both --
    - Pinecone Strike deals 3 damage to target creature. If that creature would
      die this turn, exile it instead.
    - Destroy target artifact token.

Everything the current pipeline holds for it:

    face -MOVES_TO->  zone:exile
    face -CAUSES->    obj:target-creature
    face -REPLACES->  zone:exile
    face -CAUSES->    obj:target-artifact-token

No damage amount. No modality. `CAUSES` where `DEALS_DAMAGE` and `DESTROYS`
belong. A replacement with no subject. Four edges that cannot reconstruct the
card. The target is:

    Pinecone Strike
      cost:      CONSUMES_MANA {1}{R}
      modality:  choose_one_or_both
      mode[1]:
        DEALS_DAMAGE  amount=3  class=obj:type:creature
                      selector={target:1, controller:any}
        REPLACES      when=would_die_this_turn  with=(MOVES_TO zone:exile)
                      subject=@mode[1].target
      mode[2]:
        DESTROYS      class=obj:type:artifact
                      selector={target:1, is_token:true}

`Ordinary Bear -IS_A-> obj:type:creature` then connects on its own. Nothing
mints `obj:target-creature`.

## Acceptance Criteria

- [ ] `data/vocabulary/concepts.jsonl` declares every concept the pilot uses: `concept_id`, `kind` (ObjectClass / Event / Resource / Zone / Counter / State / Gate / Keyword / Operation), `label`, and `origin` (`seeded` from an existing node, or `proposed` by a card agent). The file is the sole authority on which concepts exist
- [ ] `data/vocabulary/selectors.md` defines a **closed** selector grammar covering, at minimum: `target` (count, `up_to`), `controller` (you / opponent / any / owner), `restriction` (typed predicates such as power comparisons, subtypes, supertypes, token-ness), `zone`, and `binding` (a role such as `equipped` or `enchanted`, or a back-reference like `@mode[1].target`). Any selector a card needs and the grammar cannot express is a **failure to be reported**, not a reason to widen the grammar mid-run
- [ ] `data/graph_global/card_ports.jsonl` carries **exactly 11 records** with `properties`, `installs`, `consumes`, `produces`, `costs`, `modality`, and `unresolved`
- [ ] **Every edge in a port record names a bare class from `concepts.jsonl` and carries its selector as structured edge data.** A test asserts no port record references `obj:target-creature`, `obj:creature-you-control`, `obj:up-to-one-target-creature`, or any other selector-in-the-name node
- [ ] **Every clause of every pilot face's oracle text is covered by an `oracle_span` on some port entry.** Uncovered text fails the run naming the face and the character range. Reminder parentheticals may be marked `reminder: true` and excluded from disposition, but must still be spanned
- [ ] Modality is structure: Pinecone Strike's record carries `modality: choose_one_or_both` with two modes, and the exile replacement binds its subject to mode 1's target. A test asserts the 3-damage amount is present as a number
- [ ] Alternatives are structure: Stir Up Trouble's additional cost carries both branches, with the sacrifice as a **conditional** consume and `{4}` as a peer branch, not a string inside a node id
- [ ] Conditions are executable or explicitly marked otherwise: Elrond's `only_once_each_turn` and `up_to` both land **on the port entry they qualify**. Today all 23 executable conditions in `conditions.jsonl` are orphans attached to nothing; a test asserts zero orphans among the pilot's conditions
- [ ] The watcher rule holds: Bifur installs `storied` and Smaug does not, from the same inputs. `QUALIFIES_FOR` is classified watcher-derived and never appears as a card output. Smaug carries `supertype:legendary` as a property and lets the watcher's criterion match it
- [ ] Role bindings are edges, not classes: Wizard's Staff grants prowess to `binding: equipped`, not to a concept named `obj:equipped-creature`
- [ ] The Adventure ownership rule is stated in `selectors.md` and tested: Bofur's `lifelink` and `subtype:dwarf` belong to `:0`, `type:instant` and `subtype:adventure` to `:1`
- [ ] **Every ability on all eleven faces reaches exactly one disposition** -- produces, installs, grants a keyword, is consumed as a cost, or is `unresolved` with clause text and a recorded reason. The run prints the tally and fails if any ability is unaccounted for
- [ ] The seven abilities dead in the frozen graph across these faces (Mountain-king's Return 2, Wizard's Staff 3, Rampager 2) resolve to a non-`unresolved` disposition. A test names any that do not
- [ ] `data/vocabulary/proposals.jsonl` records every concept a card agent wanted and could not find, with the face, the clause, a rule citation, and why nothing existing fits. **A card agent may propose; it may not coin.** A port record referencing an undeclared concept fails the run
- [ ] An **overseer pass** runs once after all eleven faces and emits `reports/vocabulary_pilot.md`: concepts seeded, concepts promoted from proposals, merges performed with reasons, and any proposal rejected. The overseer is the only role permitted to write `concepts.jsonl`
- [ ] Two serial runs produce byte-identical `card_ports.jsonl`, `concepts.jsonl` and `proposals.jsonl`
- [ ] Additive only: `nodes.jsonl`, `edges.jsonl` and `conditions.jsonl` are byte-identical after the run
- [ ] `src/hobkg/ports.py` imports nothing from `assemble`, `completeness`, `equip`, `effect_semantics`, `audit` or `audit_repair`. A test asserts this
- [ ] Ruff (`E,F,I,B,UP`, line length 100) and `mypy --strict` both report zero on `src/hobkg/ports.py` and `tests/test_ports.py`, with config scoped to those two files in `pyproject.toml`. The rest of the tree is untouched
- [ ] `hobkg ports --face <id>` prints one face's interface; `hobkg ports --validate` re-checks the emitted records against the vocabulary and grammar
- [ ] The implementer commits its own work with a readable trailer block carrying `Role: worker`, `Phase: ports-v1` and an `Iteration`, per INSTRUCTIONS.md section 8. The controller refuses to commit on the implementer's behalf and halts naming the SHA if the trailers are absent
- [ ] The commit leaves the working tree clean

## Requirements

- Seed the vocabulary from what exists, then govern it. The 120 concepts touched by more than one card are the starting vocabulary; the 203 singletons are candidates, most of which are selector variants that should not survive as concepts. Seeding is a one-time read of `nodes.jsonl`; after that `concepts.jsonl` is authoritative
- `nodes.jsonl` is a vocabulary seed and `edges.jsonl` is a control. Read `edges.jsonl` only to identify the seven dead abilities and to compare coverage. Building ports over the frozen edges is the mistake this card replaces: that graph holds functional content for 276 of 418 abilities where the extraction holds 417
- Join the two identifier families by oracle span. `llm_accepted` and the graph nodes use LLM slugs; the census and `effect_records` use positional `#aN`. They are ~83% disjoint, positional joining is wrong on 75 of 210 faces, and where both look ordinal the extraction is 1-based against a 0-based census. Span overlap resolves 210 of 210 and is many-to-one, since one census clause can span several extraction spans
- Do not re-extract from Oracle text where the extraction already answers. `llm_accepted` carries kind, trigger, conditions, effects, controller, keyword, spans and confidence. The agent's work is classification, selector construction and gap-filling, not starting over
- Never mint a concept mid-record. Propose it, keep working, let the overseer decide
- Do not widen the selector grammar to make a card fit. Report the card and the construct. A grammar that grows once per card is not a grammar
- Do not rewrite the frozen base. This layer is additive
- A keyword ability is a disposition, not an absence: `Flying` resolves as a keyword grant, not as unresolved
- A watcher-installing ability legitimately produces no operation. Bifur's Storied ability resolves as `installs`, not as `unresolved`
- Ten cards, not 193. Card 002 templates one face per cycle for the remaining 183, and is written only after this card's vocabulary and grammar survive review

## Notes

**Why the pilot exists.** Measured 2026-09-03 at `3f7535f`: layer 2 as a
bipartite graph is **1,459 card-to-concept edges over 323 concepts**. Layer 3,
the one-mode projection of exactly that, is **21,758 distinct ordered pairs**
(37,314 with multiplicity). A **15x expansion**.

The previous build materialised the expansion before the 1,459 were settled.
The build spec's completion criteria require a projection record for all 37,249
ordered pairs including empties, while modelling principle 4 of the same spec
says pair relations are derived views. The gate contradicted the principle, the
gate won, and every correction to one atomic fact then had to propagate through
a materialised derivative. That is the source of the repair rounds through pt18.
**Layer 2 appears nowhere in the build spec as a deliverable**, which is why it
does not exist.

**What goes wrong without a governed vocabulary.** There are **48 distinct
concept nodes containing the word "creature"**:

    125 cards  obj:type:creature
     23 cards  obj:target-creature
     17 cards  obj:creature-you-control
      9 cards  event:this-creature-dies
      9 cards  event:this_creature_dies         <- same event, underscore
      5 cards  obj:equipped-creature
      3 cards  obj:objectclass-creatures-you-control
      1 card   obj:target-creature-with-power-4-or-greater
      1 card   obj:up-to-one-target-creature
      1 card   obj:another-target-creature-you-control
      ... 38 more, nearly all touched by exactly one card

203 of the 323 concepts are singletons. String normalisation finds only 10
collision groups covering 21 concepts -- the underscore/hyphen kind. That is the
small part. **The real problem is that selectors are baked into node names.**
`obj:target-creature` is not a different concept from `obj:type:creature`; it is
that class plus a targeting quantifier plus a controller scope. The fix is not
to merge strings; it is to put the class on the node and the selector on the
edge, so no card ever mints a variant.

**The cycle phase is `ports-v1`, not `effect-4f`.** Every setup commit made on
2026-09-02 carries `Role: worker` and `Phase: effect-4f`, so
`GitRepo.awaiting_review(phase='effect-4f')` returns the newest of them and the
controller would resume against a task-card edit rather than running this work
item. A distinct phase keeps the setup commits out of this cycle's view without
rewriting history.

**Amended three times.** This card began as "classify every unclassified census
clause", became a ports layer over the frozen graph, then a ports layer over
`llm_accepted`. This revision narrows it to a pilot and adds the two artifacts
the earlier versions assumed into existence: the concept vocabulary and the
selector grammar. Without those, 193 independent card agents produce 193 private
vocabularies and reconciliation is quadratic.

**A correction to an earlier revision.** A previous version required Bifur's
`a3` to appear in `unresolved` as a genuine hole. It is not. `llm_accepted`
carries it complete -- `op: duplicate_trigger`, gated on `state:enduring_story`,
confidence high. It was lost in assembly. The requirement is withdrawn and its
inverse is an acceptance criterion above.

**Scope note on the 142.** Across the whole set, 142 abilities have no outgoing
edge in the frozen graph and 141 survive every additive tier. That number counts
*silence*, not *error*. Stir Up Trouble and Elrond both have zero dead abilities
and both are wrong: Stir's graph says it always sacrifices a permanent when it
could instead pay {4}; Elrond's says it draws on every creature-ability
activation rather than once each turn. Four of the ten pilot cards were chosen
because they fail loudly and six because they fail quietly.

## Reviewer Notes

The reviewer checks semantics against the comprehensive rules. It does **not**
spend its judgement on bookkeeping -- the acceptance criteria are machine-checked
before review. Report a finding when:

- an edge's predicate misstates the rules effect (a damage effect recorded as `CAUSES`; a destroy recorded as a zone change)
- a selector is wrong in a way the grammar permits (missing `another`, wrong controller scope, a target count that does not match the text)
- a replacement or delayed effect is modelled as an immediate one, or its subject binds to the wrong object
- a cost is modelled as an ability, or an ability as a cost
- a triggered ability's event does not match the printed trigger condition
- a proposed concept duplicates a seeded one, or a seeded one is used for something it does not mean
- a card's ports would let a simulator do something the rules forbid, or forbid something the rules allow

Cite the comprehensive rule by number. A finding without a rule citation or an
oracle span is not actionable.
